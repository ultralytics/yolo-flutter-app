# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, etc.) when working with code in this repository. CLAUDE.md is a symlink to this file.

This repo is `ultralytics_yolo` (pub.dev, AGPL-3.0), the official Ultralytics Flutter plugin for running YOLO models on Android and iOS: single-image inference (`YOLO`), a real-time camera platform view (`YOLOView`), and the full camera UI (`YOLOShowcase`), covering detect, segment, semantic, depth, classify, pose, and OBB. Dart lives in `lib/`, Kotlin plus a small C++ JNI library in `android/`, Swift in `ios/`, the published Google Play example app in `example/`, and the pub.dev-facing docs in `doc/`. The package version is `version:` in `pubspec.yaml`.

## Core Principles (CRITICAL)

**Less is more. The simplest solution is the best solution.** The action hierarchy for every change: **Delete > Replace > Add**.

1. **Solve at the owner**: Put behavior in the code path that owns or observes it. For fixes, never guard a symptom with a staleness check, initialization flag, skip-first-call branch, or `try/except` around broken logic; relocate the trigger and delete the wrong path. For features, extend the existing owner rather than creating a parallel abstraction.
2. **Search and reuse first**: Search the whole repository before creating a feature, component, helper, workflow, or utility. Reuse or adapt what exists, consolidate in-scope duplication in the shared owner, and delete duplicate paths. Three similar lines beat a helper nobody else calls.
3. **Delete and modify existing code before creating new code**: Bugfixes are net-negative by default unless deletion and relocation are demonstrably impossible. A new file must first prove it cannot fit cleanly in an existing owner.
4. **Keep scope minimal**: Implement only the simplest complete solution. Avoid impossible-state handling, speculative flags, compatibility shims, policy scaffolding, and unrelated cleanup. Tests are out of scope by default — rely on existing coverage and focused validation; only an uncovered, high-risk regression path justifies minimal new test code.
5. **Ship zero-regression, production-ready changes**: Understand what you remove instead of retaining broken code as insurance. Remove unused imports, functions, types, files, and comments; run relevant cleanup checks; and thoroughly debug and validate the changed owner. Do not break existing features or workflows unless the PR intentionally removes them with evidence.

**Review gate:** for every addition, the reviewer decides whether deleting or changing existing code would have fixed the problem instead — if it would, that is a blocking finding. A missing or thin PR description is never itself a finding.

NEVER push to `main`. NEVER force push. Always start work in a new git worktree (`git worktree add`) on a feature branch and open a PR — never edit the primary checkout directly, it may hold in-flight work.

## PR Workflow

After opening a PR:

1. Wait for the automated PR review and auto-format commit from Ultralytics Actions (`format.yml`), then pull and address every finding.
2. Review the full diff in-session against the Core Principles, performance, and the review gate above, then batch the fixes into one commit and push. After each round of bot or human commits, pull and resume the same reviewer on `<last-reviewed-sha>..HEAD` plus anything that delta could have invalidated. Repeat until the local head matches the live head.
3. Hand off or merge only on a clean final pass: one cold full-diff review returning LGTM with no findings, on a head that is still live at merge time.
4. Never fight other commits: Ultralytics Actions pushes auto-format and header commits, and multiple users may work on the same PR. `git pull --rebase` before pushing; never reset or revert commits you did not author.
5. After the PR merges, clean up: remove local worktrees and branches for it, then `git checkout main && git pull`.

flutter test integration_test/qnn_benchmark_test.dart -d <device> --dart-define=RUN_BENCH=true  # on-device benchmark; CI never runs example/integration_test/

- CI (`ci.yml`) runs three jobs on push/PR to main: `tests` (ubuntu-latest: `flutter test --coverage`, the g++ depth-colorizer test, the lcov filter, `dart pub publish --dry-run`, Codecov upload), `example-android` (ubuntu-latest: debug APK, API 34 emulator smoke test via `adb shell pidof com.ultralytics.yolo`, release AAB verified with `scripts/build_play_store_assets.sh --verify-aab`), and `example-ios` (macos-26: SwiftPM build + simulator launch of `com.ultralytics.yoloExample`, then a CocoaPods regression build of the same sources). `analyzer.yml` runs `dart analyze --fatal-infos` as a separate check. Nothing in CI runs Kotlin/Swift unit tests or `example/integration_test/`.
- Version floors are Dart SDK `^3.8.1` and Flutter `>=3.32.1` (pubspec.yaml); CI uses the stable Flutter channel. Native floors: Android `minSdk 23` / `compileSdk 36` / NDK `28.2.13676358` unless the host app sets `ndkVersion` (android/build.gradle); iOS 13.0 (`ios/ultralytics_yolo/Package.swift`, `ios/ultralytics_yolo.podspec`). Runtime pins: LiteRT `com.google.ai.edge.litert:litert:2.1.5` + `litert-metadata:1.4.2`, `compileOnly` `com.microsoft.onnxruntime:onnxruntime-android-qnn:1.26.0`, `UltralyticsYOLO >= 8.9.14, < 9.0` (both iOS manifests must move together).
- Model export requires `ultralytics>=8.4.142`: LiteRT uses `nms=None` for raw one-to-many outputs, while Core ML assets use `nms=False` for the NMS-free head. `end2end` describes graph metadata; use `nms` to configure exports.
- For the Python model-export tooling use `uv pip install`, never bare `pip install` (see the header of `scripts/export-tflite-models.py`): `uv venv --python 3.12 .venv && uv pip install --torch-backend cpu "ultralytics-opencv-headless[export-litert]>=8.4.142" && uv run python scripts/export-tflite-models.py --verify` (add `--upload --repo ultralytics/yolo-flutter-app --tag v0.6.6` to replace release assets with `gh release upload --clobber`).

All in `.github/workflows/`:

A `workflow_dispatch` trigger exists but the job `if:` still requires `refs/heads/main`.
- `publish-on-tag.yml` — on `v*` tag push: `dart pub publish --dry-run` (with the same `Package.swift` assertion) then `dart pub publish --force` via OIDC trusted publishing. This is the workflow that actually publishes.
- `tag.yml` — manual (`workflow_dispatch`) tag + release fallback, same repo/actor gate.
- `cla.yml` — Ultralytics CLA check on `pull_request_target` and `recheck`/signature comments.
- `stale.yml` — daily stale bot (issues stale at 30 days, PRs at 90).
- `.github/dependabot.yml` — weekly `pub` and `github-actions` update PRs, three open at a time each.

## Conventions

- Every source file opens with the `Ultralytics 🚀 AGPL-3.0 License - https://ultralytics.com/license` header in the language's comment style; Ultralytics Actions adds them automatically — don't add or revert them manually.
- `format.yml` (Ultralytics Actions) auto-formats Dart, Swift, Python, and Prettier targets (YAML/JSON/Markdown) directly on PR branches, so `git pull --rebase` before pushing follow-up commits.
- Linting is `dart analyze --fatal-infos` against `analysis_options.yaml` (flutter_lints plus extra rules — e.g. `prefer_single_quotes`, `always_declare_return_types`, `avoid_print`). The analyzer excludes `android/`, `ios/`, and generated files; `very_good_analysis` is a dev dependency but is not included by `analysis_options.yaml`.
- Dart tests in `test/` run against mocked method channels (`test/utils/test_helpers.dart`) — no live network; `example/integration_test/` holds manual on-device QNN tests that CI does not run.
- Releases: bump the version in `pubspec.yaml`, `ios/ultralytics_yolo.podspec`, and `example/pubspec.yaml` (Play Store build number) together and add a `CHANGELOG.md` entry; merging to main then auto-tags and publishes via `publish.yml`.
- `.pubignore` controls the pub.dev payload (model binaries, `play-store-assets/`, and agent docs are excluded); `dart pub publish --dry-run` in CI catches payload regressions, and `publish.yml` additionally asserts `Package.swift` ships in the archive.
- `CHANGELOG.md` entries are `## X.Y.Z` headings with `- **Fix**: ...` / `- **Feature**: ...` bullets; `scripts/build_play_store_assets.sh` extracts the current version's bullets (stripping `**` and backticks) as the Play "what's new" text and warns above 500 bytes.
- Never commit model weights: the root `.gitignore` blocks `*.tflite`, `*.mlpackage`, `*.mlpackage.zip`, `*.onnx`, `*.pt`, and friends. Official assets are GitHub release attachments, fetched at runtime by the resolver or at build time by `scripts/fetch_bundled_models.sh`.
- `YOLOTask` (`lib/models/yolo_task.dart`) defines the canonical task order `detect, segment, semantic, depth, classify, pose, obb`; `YOLOModelResolver` generates the 35 official IDs from it. Kotlin parses the wire name with `YOLOTask.valueOf(task.uppercase())`, Swift with `YOLOTask.fromString` (from the `UltralyticsYOLO` package).

## Architecture

Paths are relative to the repo root. `lib/` is the Dart package, `android/src/main/kotlin/com/ultralytics/yolo/` the Android plugin, `ios/ultralytics_yolo/Sources/ultralytics_yolo/` the iOS plugin.

**Request flow.** Both Dart entry points go through `YOLOModelResolver.resolve()` (`lib/core/yolo_model_resolver.dart`) before touching native code: `preparePath()` turns the user's `modelPath` — official ID (`yolo26n`), Flutter asset (`assets/...`), `http(s)` URL, `internal://` reference, or absolute path — into something the native side can open (downloading and extracting into `<documents>/mobile-standard-v1/` as needed), then `inspect()` calls the native `inspectModel` to read exported metadata and settles the task (an explicit `task` that contradicts metadata throws `ModelLoadingException`; no task anywhere also throws). *Single image:* `YOLO.loadModel()` (`lib/yolo.dart`) → `YOLOModelManager.loadModel()` → `loadModel` on the `yolo_single_image_channel` MethodChannel → the native instance manager builds a per-instance predictor; `YOLO.predict(bytes)` → `YOLOInference.predict()` → `predictSingleImage` → the native side decodes the image, runs the predictor, and returns a raw map (`boxes` plus task keys) that `_processInferenceResult` reshapes into `detections` (`YOLOResult.fromMap`-compatible). *Camera:* `YOLOView` (`lib/yolo_view.dart`) resolves the model, then embeds the `com.ultralytics.yolo/YOLOPlatformView` platform view with `creationParams`; the native factory creates a Kotlin/Swift `YOLOView`, a control MethodChannel and a detection EventChannel both suffixed with the Dart-side `viewId` (a `UniqueKey().toString()`); per-frame results stream native → Dart on the event channel, commands go Dart → native through `YOLOViewController` (`lib/widgets/yolo_controller.dart`).

**Platform channel contract** (names are string literals on all three sides — change them together):

- `yolo_single_image_channel` (`ChannelConfig.singleImageChannel`, `lib/config/channel_config.dart`), handled by `YOLOPlugin.kt` `onMethodCall` and `YOLOPlugin.swift` `handle`: `createInstance` (registers `yolo_single_image_channel_<instanceId>`), `loadModel` (`modelPath`, `task`, `useGpu`, `numItemsThreshold`, `classifierOptions`, `instanceId`), `predictSingleImage` (`image` bytes, `confidenceThreshold`, `iouThreshold`, `instanceId`), `inspectModel`, `checkModelExists`, `getStoragePaths`, `setModel` (needs the **integer** platform view id; the Dart `YOLO.switchModel` path uses it, `YOLOViewController.switchModel` does not), `disposeInstance`, `predictorInstance` (Android warms the lazy predictor on `Dispatchers.IO`; iOS no-op). Error codes the Dart `YOLOErrorHandler` (`lib/utils/error_handler.dart`) maps: `MODEL_NOT_FOUND`, `INVALID_MODEL`, `UNSUPPORTED_TASK`, `MODEL_FILE_ERROR`, `MODEL_NOT_LOADED`, `INVALID_IMAGE`, `IMAGE_LOAD_ERROR`, `INFERENCE_ERROR`; anything else becomes `InferenceException`.
- Platform view `com.ultralytics.yolo/YOLOPlatformView` creation params (`_buildCreationParams` in `lib/yolo_view.dart`): `modelPath` (already resolved), `task`, `confidenceThreshold`, `iouThreshold`, `numItemsThreshold`, `viewId`, `useGpu`, `lensFacing` (`back`/`front`/`backWide`; iOS treats anything but `front` as back), optional `streamingConfig` map.
- Control channel `com.ultralytics.yolo/controlChannel_<viewId>` (`YOLOPlatformView.kt` `onMethodCall`, `SwiftYOLOPlatformView.swift` `setupMethodChannel`): `setConfidenceThreshold`, `setIoUThreshold`, `setNumItemsThreshold`, `setThresholds`, `setModel`, `switchCamera`, `setTorchMode` (returns the real resulting torch state), `setZoomLevel`, `setStreamingConfig`, `setShowOverlays`, `stop`, `pause`, `resume`, `captureFrame`, `capturePhoto` (`withOverlays`), `getAvailableLenses`, `setLens`, `tapToFocus`. Android-only: `restartCamera`, `reconnectStream`. iOS-only legacy: `setThreshold`. Native → Dart on the same channel: `recreateEventChannel` (Android sink-reconnect request) and `onZoomChanged` (iOS legacy). `YOLOViewController.zoomIn()`/`zoomOut()` invoke methods that neither platform implements; `_invoke` swallows the `notImplemented` error and returns null.
- Event channel `com.ultralytics.yolo/detectionResults_<viewId>`: per-frame maps built by `convertResultToStreamData` in each native `YOLOView`, gated by `YOLOStreamConfig` flags and enriched with `timestamp`, `frameNumber`, `imageWidth`, `imageHeight` (`onFrame` in `YOLOView.kt`, `onPredict` in `YOLOView.swift`). Keys: `detections` (each with `classIndex`, `className`, `confidence`, `boundingBox`, `normalizedBox`, and per task `mask`, `keypoints`, `polygon`/`polygonNormalized`, `angle`), `fps`, `processingTimeMs`, `preMs`, `inferenceMs`, `postMs`, `semanticMask`, `depthMap`, `originalImage`. Typed events `{type: "zoom"|"lens"|"focus", ...}` ride the same channel and are routed by `YOLOViewController.onNativeEvent`. Android's `CustomStreamHandler` also sends `{"test": ...}` handshake maps that carry no `detections`.

### Dart (`lib/`)

- `ultralytics_yolo.dart` — barrel. Exports everything public, including `DownloadProgress` (from `core/yolo_model_manager.dart`), `YOLOViewController`/`LensInfo` (from `widgets/yolo_controller.dart`), and every widget under `widgets/`. `core/yolo_model_resolver.dart` and `core/yolo_inference.dart` are not exported; tests import them by path.
- `yolo.dart` — `YOLO` facade. `useMultiInstance: true` mints `instanceId = 'yolo_<ms>_<hashCode>'`, registers it in `YOLOInstanceManager` (`yolo_instance_manager.dart`, a static Dart map), and suffixes the channel; the default id is `'default'` and is shared by every non-multi-instance `YOLO`. `loadModel()` lazily resolves (`_ensureResolved`) and builds `YOLOModelManager` + `YOLOInference`; `predict()` auto-loads. `switchModel()` requires `setViewId(int)` first (it drives `setModel` on the single-image channel with the platform view id). Statics: `officialModels()`, `defaultOfficialModel()`, `inspectModel()`, `checkModelExists()`, `getStoragePaths()`, `withClassifierOptions()` (keys `labels`, `enableColorInversion`, `enableMaxNormalization`, `inputMean`, `inputStd`; consumed only by Android `Classifier.kt`).
- `core/yolo_model_resolver.dart` — `YOLOModelResolver`. Pinned constants `_androidModelReleaseBaseUrl` (yolo-flutter-app `v0.6.6`, `<id>_w8a32.tflite`) and `_iosModelReleaseBaseUrl` (yolo-ios-app `v8.3.0`, `<id>.mlpackage.zip`); `_officialModels` is generated as 7 `YOLOTask` values × `_yolo26Sizes` (`n s m l x`) = 35 IDs, and YOLO11 IDs are deliberately not official. `_isIosLikePlatform` is `Platform.isIOS || Platform.isMacOS`. Resolution order in `_resolvePath`: URL → `assets/` → official ID → passthrough. Official models are cached under `<documents>/mobile-standard-v1/`; a same-named file in the documents root is treated as legacy and deleted. Bundled `assets/models/<asset>` is copied/extracted before any download (`isOfficialModelAvailableLocally` mirrors this check for UI). Downloads stream to `<target>.download`, emit `YOLOModelManager.emitProgress` capped at `0.99` until the rename succeeds, reject 0-byte bodies, and honor `YOLOModelManager.cancelDownload`. iOS archives are unpacked by `MiniZip` (`utils/mini_zip.dart`, STORED + raw DEFLATE only, strips one top-level `*.mlpackage/` directory, skips `__MACOSX/` and `._` entries) and validated by the presence of `Manifest.json`.
- `core/yolo_model_manager.dart` — `YOLOModelManager`: static broadcast `downloadProgress` stream plus the cancel registry (`registerDownload`, `cancelDownload`, `isDownloadCancelled`, `finishDownload`, `clearDownloadCancellation`), and the per-instance `initializeInstance` / `loadModel` / `switchModel` / `predictorInstance` / `dispose` channel calls.
- `core/yolo_inference.dart` — `YOLOInference.predict` validates inputs (`InvalidInputException`), invokes `predictSingleImage`, and `_processInferenceResult` builds `detections` per task from the native `boxes` (`x1..y2`, `*_norm`, `class`, `confidence`), `keypoints` (`coordinates` of `{x,y,confidence}`), `masks`, `classification` (`{name, class, confidence, top5}`), and `obb` (`points`, `angle`, `classIndex`, `class`). `_createDetectionMap` hardcodes `classIndex: 0` for detect/segment/pose because the native box map carries no index. Semantic and depth produce no `detections`; read `semanticMask`/`depthMap` from the raw map (or `YOLODetectionResults.fromMap`).
- `yolo_view.dart` — `YOLOView` + `_YOLOViewState`. `initState` resolves; `build` shows a black "Loading model…" veil until `_resolvedModel` is set, a neutral error veil on `_resolutionError`, and `AndroidView`/`UiKitView` otherwise (any other `defaultTargetPlatform` renders "Platform not supported"). `didUpdateWidget` re-resolves when `modelPath`/`task` change and, once the platform view exists, switches in place through a serialized `_nativeSwitchChain` compared against `_nativeSwitchTarget` (not `_resolvedModel`, which lags); a failed in-place switch keeps the camera running and fires `onModelError(error, modelPath, task)` while `onModelLoad(modelPath, task)` fires only on success. `_onPlatformViewCreated` initializes the controller (which replays thresholds and a pre-attach `setShowOverlays(false)`), pushes `streamingConfig`, and subscribes to the event channel; `dispose` sends `disposeInstance` with the string `viewId` on the single-image channel.
- `widgets/yolo_controller.dart` — `YOLOViewController`. `_invoke` returns `null` on any error (logged in debug only), so most controls are fire-and-forget; `switchModel` deliberately rethrows so `YOLOView` can revert. Exposes `zoomEvents`/`lensEvents`/`focusEvents` broadcast streams, `capturePhoto`, `pause`/`resume` (iOS snapshots a share frame on pause; Android unbinds use cases and `resume` = `restartCamera`), `getAvailableLenses`/`setLens`, `tapToFocus`, `setTorchMode`/`toggleTorch` (cached `isTorchEnabled` follows the native return value).
- `yolo_streaming_config.dart` — `YOLOStreamingConfig` flags and presets (`minimal`, `custom`, `withMasks`, `withPoses`, `full`, `debug`, `throttled`, `powerSaving`, `highPerformance`). `skipFrames` beats `inferenceFrequency`; `maxFPS`/`throttleInterval` gate output, not inference; `analysisResolution` is Android-only (sent as `analysisWidth`/`analysisHeight`; the iOS `YOLOStreamConfig.from(dict:)` ignores it).
- `models/` — `yolo_result.dart` (`YOLOResult`, `YOLODetectionResults`, `YOLOSemanticMask`, `YOLODepthMap`, `Keypoint`; `fromMap`/`toMap` are the channel schema), `yolo_task.dart` (`YOLOTask`, `modelSuffix`, `label`, `shortLabel`, `tryParse`), `yolo_exceptions.dart`. `yolo_performance_metrics.dart` — `YOLOPerformanceMetrics.fromMap` reads `fps`, `processingTimeMs`, `frameNumber`, `preMs`, `inferenceMs`, `postMs`.
- `utils/` — `error_handler.dart` (code → exception mapping above), `map_converter.dart` (`safeGet*`, `convertBoundingBox`, `convertKeypoints` for flat `[x,y,c,...]`, `convertMaskData`), `logger.dart` (`logInfo`, `kDebugMode` only), `mini_zip.dart`.
- `platform/` — `YOLOPlatform`/`YOLOMethodChannel` (`plugin_platform_interface` scaffolding exposing only `setModel`). Nothing on the main path uses it; `YOLO` and `YOLOView` talk to channels directly.
- `widgets/yolo_showcase.dart` — `YOLOShowcase`, the one-import camera UI that composes `YOLOView` with `TaskSegmentedControl`, `ModelSizeSegmentedControl`, `ThresholdSliderRow`, `LensPicker`, `CameraToolbar`, `PerformanceLabel`, `ZoomIndicator`, `FocusReticle`, `LogoOverlay` (each in its own `widgets/*.dart`). Persists the last task under SharedPreferences key `ultralytics_yolo.showcase.task`, enables `WakelockPlus`, tracks optimistic (`_currentTask`/`_currentSize`) versus native (`_runningTask`/`_runningSize`) selection and reverts on `onModelError`, subscribes to `YOLOModelManager.downloadProgress` for the size-chip progress bar, marks sizes available via `YOLOModelResolver.isOfficialModelAvailableLocally`, and drives high-frequency HUD values through `ValueNotifier`s rather than `setState`. `onCapture` receives the JPEG from `controller.capturePhoto()`.

### Android (`android/`)

- `YOLOPlugin.kt` — `FlutterPlugin` + `ActivityAware`. Registers the platform view factory and the default channel; `createInstance` registers per-instance channels handled by the same class; `resolveModelPath` expands `internal://` against `filesDir`; `setModel` looks up `viewFactory.activeViews[viewId]` (platform int id); `predictSingleImage` decodes with `BitmapFactory`, runs `instanceManager.predict`, and builds the response (masks as nested lists plus `maskPng`, `semanticMask.classMap` as an `IntArray`, `depthMap.values` as a `FloatArray`, `classification`, `keypoints`, `obb`, JPEG `annotatedImage`, `speed`/`preMs`/`inferenceMs`/`postMs`, `accelerator`). Permission results are forwarded to every active platform view.
- `YOLOInstanceManager.kt` — `ConcurrentHashMap<String, YOLO>`; `loadModel` uses `putIfAbsent`, so a second `loadModel` for an existing id keeps the first model and still reports success; `predict` swaps thresholds under `synchronized(yolo)` and restores them.
- `YOLO.kt` — facade owning a lazy `Predictor` (`Predictor.create`); `predict(bitmap)` renders `drawAnnotations` (skipped for classify), `predict(ImageProxy)` is the camera path with rotation handling, `close()` marks the instance closed.
- `Predictor.kt` — `InferenceModel` (`accelerator`, `inputDims` always reported NHWC, `inputUsesNchw`, `outputDims`, `outputElementCounts`, `run(FloatArray): List<FloatArray>`) with `InferenceModel.create`: paths ending `_qnn.onnx` → `OrtQnnModel`, any other `.onnx` is rejected, everything else → `LiteRtModel`. `Predictor.create` maps `YOLOTask` → `ObjectDetector`, `Segmenter`, `SemanticSegmenter`, `DepthEstimator`, `Classifier`, `PoseEstimator`, `ObbDetector`. `BasePredictor` holds thresholds, `finishTiming` (EMA fps plus pre/inference/post split), `labelName`, and the letterbox coordinate helpers (`inputRectFromOutputRect`, `inputPointFromOutputPoint`, `inputOBBFromModelOBB`, `modelMaskCropRect`) that auto-detect normalized (≤2) vs model-pixel outputs; boxes are intentionally not clamped to the frame.
- `LiteRtModel.kt` — LiteRT 2.x `CompiledModel`. `useGpu` tries `Accelerator.GPU` first (program cache in `codeCacheDir`, keyed by file name + size) and falls back to CPU (`numThreads = availableProcessors().coerceIn(1, 4)`). Input shape is read by name (`images`, `args_0`, `input`, `input_1`, `serving_default_input`), else inferred as a square NHWC image from the buffer size; NCHW is detected when dim 1 is 3 and the last dim is not. A zero-input warm-up run happens inside the fallback path. Output names are probed as `output_N`, `outputN`, then `Identity`/`Identity_N`; a miss leaves that `outputDims` entry empty (detect/obb/classify survive via element counts, segment/semantic/pose do not). Outputs are read by declared element type.
- `OrtQnnModel.kt` — ONNX Runtime QNN EP (`backend_path=libQnnHtp.so`, `htp_performance_mode=burst`), sets `ADSP_LIBRARY_PATH` to the APK's `nativeLibraryDir`, loads from an absolute file or Flutter assets, reuses output buffers, no CPU fallback (a `LinkageError` from the missing optional dependency surfaces as an `IllegalStateException` naming the Gradle artifact).
- Task predictors — `ObjectDetector.kt` (JNI `postprocess` NMS in `android/src/main/cpp/native-lib.cpp`; end-to-end `[1, N, 6]` outputs detected when `out2 < out1 && out2 >= 6` and decoded in Kotlin), `Segmenter.kt` (two outputs in arbitrary order — the rank-3 head and rank-4 proto — with proto layout NCHW vs NHWC detected by where the 32 mask coefficients sit), `SemanticSegmenter.kt` (4D logits in either layout or a 3D in-graph-ArgMax class map), `DepthEstimator.kt` (JNI `colorizeDepth` → `depth-colorizer.h`, the only C++ covered by a CI test), `Classifier.kt` (1-channel grayscale models detected from `inputDims[3] == 1`; center-crop preprocessing; `classifierOptions`), `PoseEstimator.kt` (keypoint count derived from the feature width, so non-COCO skeletons work), `ObbDetector.kt`. `ImageUtils.kt` owns letterbox math (`letterboxTransform`, `prepareBitmapForModel`, `copyRgbBitmapToFloatArray` with `channelsFirst`) and RGBA `ImageProxy` → `Bitmap`.
- `YOLOFileUtils.kt` — metadata: `loadModelMetadata` tries the Ultralytics appended ZIP (`metadata.json` / `TFLITE_ULTRALYTICS_METADATA.json`, found by scanning the last ~64 KB for a local-file-header signature), then standard FlatBuffers metadata via `MetadataExtractor` (`litert-metadata`), and for `.onnx` the protobuf `metadata_props` (field 14) parsed by hand; returns `task`, `labels` (sorted by numeric key), `description`, `stride`, `channels`, `end2end`, `imgsz`. `Utils.kt`: `ensureTFLiteExtension` (appends `.tflite` unless `.tflite`/`.onnx`), `loadModelFile`, `checkModelExistence`, `ultralyticsColors`.
- `YOLOView.kt` (~2.5k lines) — CameraX `FrameLayout` + `DefaultLifecycleObserver`. `setModel(path, task, useGpu, callback)` keys an LRU predictor cache (`predictorCacheLimit = 3`, key `"$modelPath|$task|$useGpu"`), builds a new predictor on a throwaway single-thread executor, and on failure keeps the previous predictor (only an initial failure leaves "No Model"). `startCamera()` is a no-op until a predictor exists, binds a 4:3 preview plus an RGBA_8888 `ImageAnalysis` (optional `ResolutionSelector` from `analysisWidth`/`analysisHeight`), and guards stale frames with `cameraGeneration`. `pauseCamera()` unbinds use cases but keeps the predictor; `stop()` closes the predictor and every cached predictor. `onFrame` runs inference, applies `shouldRunInference`/`shouldProcessFrame` throttling, and invokes the stream callback; `emitEvent` sends typed zoom/lens/focus maps; lens enumeration, `setLens`, `tapToFocus`, `setTorchMode`, `capturePhoto`/`captureFrame` (JPEG with optional overlay composite) live here too.
- `YOLOPlatformView.kt` / `YOLOPlatformViewFactory.kt` — parse `creationParams`, build `YOLOStreamConfig.kt` (`analysisWidth`/`analysisHeight` included), forward stream data with a 500 ms retry that asks Dart to `recreateEventChannel` when the sink is gone; `CustomStreamHandler` holds the `EventSink`. `dispose()` stops the view, detaches the lifecycle observer, and unregisters from `activeViews`.
- Build: `android/build.gradle` (AGP 8.11.1, Kotlin 2.2.20 applied only when AGP < 9 or `android.builtInKotlin=false`, ABIs `armeabi-v7a arm64-v8a x86 x86_64`, `consumer-rules.pro` keep rules for LiteRT/TFLite/SnakeYAML/JNI shipped to consumers), `src/main/cpp/CMakeLists.txt` (builds `libultralytics.so`, loaded by `System.loadLibrary("ultralytics")` in `ObjectDetector` and `DepthEstimator`), `src/main/AndroidManifest.xml` (declares `CAMERA`).

### iOS (`ios/`)

The inference core (Core ML loading, metadata, per-task predictors, `BasePredictor.create`) is the shared `UltralyticsYOLO` Swift package from yolo-ios-app, pulled by both `ios/ultralytics_yolo/Package.swift` and `ios/ultralytics_yolo.podspec` (same version range; `Sources/ultralytics_yolo/README.md` explains the split). This directory is only the Flutter bridge and camera/view layer; the bridge classes are `@MainActor` and use `@preconcurrency import Flutter` for Swift 6 strict concurrency.

- `YOLOPlugin.swift` — default channel handler. `inspectModel` runs off-main and **compiles the model** (`MLModel.compileModel` unless already `.mlmodelc`) to read `creatorDefinedKey` metadata (`task`, `names` parsed by `BasePredictor.parseLabels`, `imgsz`, `stride`, `channels`, `end2end`). `checkModelExists` searches `flutter_assets/<dir>`, `flutter_assets`, bundle resources, `.mlmodelc`, `.mlpackage`. `setModel` on this channel requires an `Int` viewId; a string viewId returns `NOT_IMPLEMENTED`.
- `YOLOInstanceManager.swift` — singleton keyed by instanceId. `loadModel` returns success immediately if an instance exists, coalesces concurrent loads, keeps the loading `YOLO` alive in `pendingLoads` (the package captures `self` weakly), and uses `loadGeneration` so a superseded or disposed load cannot resurrect an instance. `resolveModelPath` searches `flutter_assets/...` variants then `Bundle.allBundles`. `convertToFlutterFormat` mirrors the Android response (`speed` converted to milliseconds; `depthMap.values` as `FlutterStandardTypedData(float32:)`).
- `SwiftYOLOPlatformView.swift` / `SwiftYOLOPlatformViewFactory.swift` — create `YOLOView(frame:modelPathOrName:task:useGpu:cameraPosition:)`, register it in an `NSLock`-guarded registry by `Int(viewId)`, and handle the control channel; thresholds are applied by setting the native `sliderConf`/`sliderIoU`/`sliderNumItems` values and calling `sliderChanged`. Typed zoom/lens/focus events go out on the event sink (zoom also on the legacy `onZoomChanged` method call). `deinit` stops the camera and removes the instance.
- `YOLOView.swift` (~2k lines) — `UIView` + `VideoCaptureDelegate`. `setModel` accepts an absolute `.mlmodel`/`.mlpackage`/`.mlmodelc` path or a `Bundle.main` resource name; **a path it cannot find logs "Camera will run without inference" and completes with success**. LRU predictor cache (`predictorCacheLimit = 3`, key `path|task|useGpu`); new predictors come from `BasePredictor.create(for:modelURL:isRealTime:useGpu:)` with thresholds and `capturesOriginalImage`/`capturesInstanceMasks` applied after load. `onPredict` draws overlays (`showBoxes`/`showOBBs`, mask and pose layers positioned with `imageFrameInOverlay`) and emits stream data; `capturePhoto` composites overlays via `renderShareImage`; `pause`/`resume`, `setZoomLevel`, `availableLenses`/`setLens`, `tapToFocus`, `setTorchMode` mirror yolo-ios-app.
- `VideoCapture.swift` — `AVCaptureSession` (default preset `.hd1280x720`); requests camera permission itself on first use (the host app must declare `NSCameraUsageDescription`); `captureNextFrame` feeds `capturePhoto`. `BoundingBoxView.swift`, `YOLOOverlayStyle.swift`, `YOLOStreamConfig.swift` (`from(dict:)`), `YOLOCamera.swift` (SwiftUI wrapper, not used by the Flutter bridge), `PrivacyInfo.xcprivacy` (bundled as a SwiftPM resource and a CocoaPods resource bundle).

### Official model assets and publishing

Official model IDs (e.g. `yolo26n`) are resolved by `lib/core/yolo_model_resolver.dart` to pinned GitHub release assets: Android LiteRT `.tflite` and opt-in QNN `.onnx` from yolo-flutter-app `v0.6.6`, and iOS Core ML `.mlpackage.zip` from yolo-ios-app `v8.3.0`. These tags are intentionally pinned and duplicated in `scripts/fetch_bundled_models.sh` — keep both in sync when regenerating assets (`scripts/export-tflite-models.py` for Android; the iOS assets come from the yolo-ios-app repo). QNN assets are not resolved by model ID (the resolver only knows `_w8a32.tflite` and `.mlpackage.zip`); pass their release URL or file path explicitly.

**Cross-platform model parity is mandatory:** Android and iOS must expose all 35 official YOLO26 IDs (five sizes across detect, segment, semantic, depth, classify, pose, and OBB). Never filter an official task or size by platform without explicit user approval. Any catalog change must keep the platform-independent 35-model URL test and must be validated on physical Android and iOS devices before the PR is called production-ready.

Publishing is push-triggered: `publish.yml` runs on every push to main (gated to `ultralytics/yolo-flutter-app` and actor `glenn-jocher`), compares the pubspec version against pub.dev via `ultralytics-actions`, and when it is ahead tags `vX.Y.Z` and creates a GitHub release; the tag push then fires `publish-on-tag.yml`, which does the actual `dart pub publish --force` through pub.dev trusted publishing. `tag.yml` is a manual (workflow_dispatch) tag/release fallback.

## Where to look

- Model path not found / wrong task / "Could not determine the task" → `YOLOModelResolver.resolve` and `_resolvePath` in `lib/core/yolo_model_resolver.dart`; native metadata readers `YOLOFileUtils.loadModelMetadata` (Android) and `YOLOPlugin.inspectModel` (iOS); path expansion in `YOLOPlugin.kt` `resolveModelPath`, `YOLOInstanceManager.swift` `resolveModelPath`, and `YOLOView.swift` `setModel`.
- Official model download, caching, progress bar, cancel → `_downloadToFile`, `_resolveAndroidOfficialModel`, `_resolveIosOfficialModel` in the resolver; `YOLOModelManager` statics; `_progressSub` in `lib/widgets/yolo_showcase.dart`.
- Changing the official asset set or release tag → resolver constants, `scripts/fetch_bundled_models.sh` (tags and file lists), `scripts/build_play_store_assets.sh` (bundled-file allowlist in the stash loop), `scripts/export-tflite-models.py` `DEFAULT_TAG`, the 35-ID URL test in `test/yolo_test.dart`, and the tables in `README.md`, `doc/models.md`, `example/README.md`.
- Single-image result shape or a missing field → native response builders (`predictSingleImage` in `YOLOPlugin.kt`, `convertToFlutterFormat` in `YOLOInstanceManager.swift`) and the Dart reshaper `_processInferenceResult` in `lib/core/yolo_inference.dart`; typed parsing in `YOLOResult.fromMap` / `YOLODetectionResults.fromMap`.
- Camera stream payload, FPS, throttling → `convertResultToStreamData`, `shouldRunInference`, `shouldProcessFrame`, `setupThrottlingFromConfig` in `YOLOView.kt` and `YOLOView.swift`; Dart side `_handleEvent` in `lib/yolo_view.dart` and `YOLOPerformanceMetrics.fromMap`.
- Adding a control-channel command → `YOLOViewController` (Dart), `YOLOPlatformView.kt` `onMethodCall`, `SwiftYOLOPlatformView.swift` `setupMethodChannel`, then the `YOLOView` method on each platform, and the mock in `test/utils/test_helpers.dart` if a Dart test drives it.
- Adding a streaming-config field → `YOLOStreamingConfig` + `_buildCreationParams`/`setStreamingConfig` (Dart), `YOLOStreamConfig.kt` + both parse sites in `YOLOPlatformView.kt`, `YOLOStreamConfig.swift` `from(dict:)`.
- Android inference wrong on a custom model → input/output naming and layout detection in `LiteRtModel.prepareModel`; per-task shape handling in the predictor `init` blocks; coordinate mapping in `BasePredictor`; metadata in `YOLOFileUtils`.
- GPU vs CPU vs NPU selection → `LiteRtModel` accelerator ladder, `InferenceModel.create` in `Predictor.kt`, `OrtQnnModel`; the `accelerator` string reaches Dart in the single-image response. On iOS `useGpu` is handed to `YOLO(...)`/`BasePredictor.create(...)` in the `UltralyticsYOLO` package (not in this repo); `accelerators` in `YOLOInstanceManager.swift` is only a label.
- Overlay drawing → Android `OverlayView` inside `YOLOView.kt` (camera) and `YOLO.drawAnnotations` (single image); iOS `showBoxes`/`showOBBs` plus the mask and pose layers in `YOLOView.swift`, `BoundingBoxView.swift`, `YOLOOverlayStyle.swift`.
- Model switching races or a stuck "Loading model…" → `_performModelResolution` / `_nativeSwitchChain` in `lib/yolo_view.dart`, `YOLOViewController.switchModel`, native `setModel` (cache fast path and failure handling) in both `YOLOView`s, `YOLOInstanceManager.swift` `loadGeneration`.
- Showcase UI state (chips, sizes, progress, errors) → `_YOLOShowcaseState` in `lib/widgets/yolo_showcase.dart` (`_onTaskChanged`, `_onSizeChanged`, `_onModelLoaded`, `_onModelError`, `_refreshAvailableSizes`), layout test in `test/yolo_showcase_layout_test.dart`.
- Release/publish problems → `publish.yml` `check` job, `publish-on-tag.yml`, `.pubignore`, `dart pub publish --dry-run` output.
- Play Store build → `scripts/build_play_store_assets.sh`, the signing block in `example/android/app/build.gradle`, `example/pubspec.yaml` `version: X.Y.Z+N`.

## Gotchas

- `flutter test` on macOS exercises the iOS-like resolver branch (`Platform.isMacOS` counts as iOS-like) while CI on ubuntu exercises the Android branch; `test/yolo_test.dart` switches expectations with `_isAppleTestPlatform`. Resolver tests write to `/tmp/yolo_test` (the mocked `path_provider` documents directory) and `_resetResolverDocuments()` deletes that directory recursively.
- Two non-multi-instance `YOLO` objects share the native `'default'` instance. Android `putIfAbsent` and iOS "already loaded → success" mean the second `loadModel` silently keeps the first model. Use `useMultiInstance: true` (or `dispose()` first) when running two different models.
- On iOS, Flutter-asset models must be `assets/models/<name>.mlpackage.zip`; the Dart resolver extracts them to documents. A bare `.mlpackage` asset path is passed through unchanged, `YOLOView.setModel` cannot find it, and the camera starts **without inference while reporting success**. On Android, `assets/...` models are copied into the documents root (not `mobile-standard-v1/`) and never refreshed once the copy exists.
- `YOLOView.onStreamingData` takes precedence: when it is set, `onResult` and `onPerformanceMetrics` are not called. `onResult` drops any detection missing `classIndex`/`className`/`confidence`/`boundingBox`/`normalizedBox`.
- Single-image `detections[].classIndex` is `0` for detect/segment/pose (the native box map has `class` = label text only); camera-stream detections carry the real `classIndex`. Semantic and depth return no `detections` at all.
- The default `YOLOStreamingConfig` excludes masks, poses, and OBB polygons. Pose keypoints, instance masks, and OBB `polygon` data only appear in camera results with `includePoses`/`includeMasks`/`includeOBB` set (Android also only fills raw mask data when `includeMasks` is on).
- `YOLOViewController` methods other than `switchModel` never throw: `_invoke` logs (debug builds only) and returns `null`, so a missing native handler looks like success. `zoomIn`/`zoomOut` have no native implementation on either platform.
- Native `setModel` keeps the previously loaded model on failure and Dart keeps the camera running; the only signal is `onModelError` plus `FlutterError.reportError`. Initial-load failures render the neutral "Unable to load the model" veil instead of the platform view.
- iOS `inspectModel` compiles the Core ML model to read metadata, so the first `YOLOModelResolver.resolve` of a large `.mlpackage` is slow; Android reads only the appended ZIP tail.
- Android metadata parsing uses `ensureTFLiteExtension`, so `assets/models/custom` and `assets/models/custom.tflite` both resolve; `.onnx` paths pass through and only `*_qnn.onnx` is accepted by `InferenceModel.create`.
- Segment/semantic/pose predictors on Android need `outputDims` populated; a custom `.tflite` whose outputs are not named `output_N`, `outputN`, or `Identity[_N]` loads (detect works from element counts) but those tasks fail in their `init` shape checks.
- Android GPU compilation is cached in `codeCacheDir` keyed by file name + size; a same-name, same-size model swap reuses the stale program cache.
- Android release builds must keep the plugin's `consumer-rules.pro` (LiteRT is invoked via JNI/reflection); the example duplicates them in `example/android/app/proguard-rules.pro`. `minSdk 23` is a LiteRT 2.x floor.
- QNN: the runtime is `compileOnly` in the plugin, so consumers (and the example) must add `onnxruntime-android-qnn` and `useLegacyPackaging = true` themselves; the example only does so with `ENABLE_QNN=1`. QNN models have no CPU fallback and are not resolved by model ID — pass the release URL or file path.
- `scripts/fetch_bundled_models.sh` is skipped whenever `CI` or `GITHUB_ACTIONS` is set, so CI builds always exercise the runtime-download fallback; locally it deletes the other platform's known nano files from `example/assets/models/` (custom files are left alone).
- Version fields are bumped by hand and can drift: at the time of writing `pubspec.yaml` is `0.6.14` while `ios/ultralytics_yolo.podspec` and `example/pubspec.yaml` are `0.6.13`; `build_play_store_assets.sh` refuses to build until the pubspec and example versions match.
- `publish.yml` only tags; `publish-on-tag.yml` publishes. If a tag exists but pub.dev is behind, re-run or re-push the tag path, not `publish.yml`.
- `format.yml` also runs Lychee link checks and codespell on PRs; broken links or spelling in Markdown are PR findings even for code-only changes.
- `YOLOShowcase` updates FPS/zoom/lens through `ValueNotifier`s on purpose — routing them through `setState` rebuilds the platform view ~30×/s and makes pinch-zoom lag.
- The Dart `YOLOInstanceManager` (`lib/yolo_instance_manager.dart`) is a process-wide static map cleared only by `YOLO.dispose()`; tests that create multi-instance `YOLO`s without disposing leak entries across tests.
